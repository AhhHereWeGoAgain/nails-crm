# Nails CRM

Локальная CRM для мастера ногтевого сервиса: календарь клиентов, сделки с канбан-доской, доходы, налоги, расходы и отчёты. **Без облака и без подписки.**

## Возможности

- Интерфейс в стиле современной CRM: голубая боковая навигация, лаконичные контурные SVG-иконки, адаптивная мобильная версия.
- **Календарь**: нажатие на любой день открывает создание сделки на эту дату; слева/справа доступна навигация по месяцам. В выбранном дне отображаются сделки и время записи клиентов.
- **Сделки / канбан**: раздел с четырьмя стадиями — «Запланировано», «В работе», «Завершено», «Отменено». Перетаскивание карточки мышью между колонками, выбор стадии в выпадающем списке на смартфоне, поиск и фильтры «Все / Клиенты / Расходы».
- Сделка «Клиент»: дата, необязательное время записи, клиент из отдельного справочника, сумма, налог 0/4/6% или пользовательский, комментарий, стадия.
- Сделка «Расход»: дата, категория, сумма, комментарий, стадия. Категории: аренда, материалы, оборудование, прочее; можно создавать свои. Для аренды предусмотрена подстановка предыдущей суммы.
- **Клиенты**: отдельная база с именем, телефоном, примечанием, историей посещений и источником. Источники по умолчанию: Авито (модель), Авито (маникюр), Телеграм, Реклама, По рекомендации. Источники можно добавлять в настройках либо прямо в карточке клиента.
- Настройки: категории расходов, источники клиентов, экспорт и импорт резервной копии JSON.
- Финансы: учёт сумм **только завершённых** сделок. Запланированные, в работе и отменённые не искажают фактическую выручку, расходы и налог. При миграции **все старые сделки остаются завершёнными**, финансовые результаты не пропадают.
- Существующая SQLite-база автоматически дополняется новыми таблицами и колонками без удаления прежних данных.
- Общие HTML/JS-исходники для веб-, desktop- и Android-WebView. Бинарный Android APK пока не входит в репозиторий.

Суммы хранятся в целых копейках. Налоги рассчитываются приближённо для внутреннего учёта; это не налоговая декларация.

## Запуск веб-версии

Нужен **Python 3.10+**, никаких `pip install` не требуется.

```bash
python server.py
```

Откройте `http://127.0.0.1:8765`. На Windows достаточно дважды нажать `run_web.bat`.

Файл базы: `~/.nails-crm/data.sqlite3` (Windows: `C:\Users\<пользователь>\.nails-crm\data.sqlite3`). Перезапуск сервера данные не удаляет.

### Веб с телефона в домашнем Wi-Fi

```bash
python server.py --host 0.0.0.0 --port 8765
```

В телефоне откройте `http://IP_ВАШЕГО_КОМПЬЮТЕРА:8765`. Все браузеры, открывшие **этот сервер**, работают с одной SQLite-базой. Устройства должны находиться в одной сети, а порт не должен блокироваться файрволом.

**Важно:** доступ по LAN сейчас **без пароля и HTTPS**. Не открывайте порт в Интернет; пользуйтесь только доверенной сетью. Для использования через Интернет нужна отдельная аутентификация и TLS.

## Нативная утилита для Windows/Linux/macOS

```bash
python -m pip install pywebview
python desktop/launcher.py
```

На Windows можно воспользоваться `run_desktop.bat`. Это отдельное окно с тем же интерфейсом и локальной SQLite-базой. Для распространения как `.exe` возможна упаковка PyInstaller, но готовый `.exe` не входит в исходники.

## Android

Android-версия предоставлена **в исходниках**. APK не собран и не проверен на реальном телефоне в этой среде.

Каталог `android/` — исходный проект для **Android Studio** (Java, Android WebView, AndroidX WebKit). Откройте в Android Studio каталог `android`, настройте Gradle 8.9 / JDK 17, дождитесь синхронизации и выполните **Build > Build APK(s)**. В архиве включён исходный Android-проект, но не включён бинарный `gradle-wrapper.jar`; если Android Studio запросит полноценный Gradle Wrapper, выполните `gradle wrapper --gradle-version 8.9` в каталоге `android` (при наличии Gradle) или создайте wrapper через инструменты IDE. Для сборки нужен Android SDK/JDK 17 и доступ к загрузке Gradle и AndroidX в момент первой сборки.

Android APK содержит те же HTML/CSS/JS файлы из каталога `web/`, работает **без сервера и без подключения к Интернету** и сохраняет записи во внутреннем хранилище WebView (`localStorage`). Для Android предусмотрен системный диалог сохранения/импорта JSON.

**Разница хранения:** браузеры, открытые через `server.py`, используют **общую SQLite**; автономное Android-приложение использует **отдельные локальные данные**. Перенести записи можно через Настройки → Скачать JSON / Загрузить JSON. Автоматическая синхронизация автономного Android-приложения с сервером пока не реализована.

Можно установить веб-интерфейс на главный экран через браузер, но на обычном HTTP-адресе в LAN установка как PWA и офлайн-режим могут быть недоступны. APK от этого не зависит.

## Безопасность и резервные копии

- Не храните реальные данные клиентов в публичном Git-репозитории: база, резервные копии и конфиденциальные файлы не должны коммититься.
- Резервную копию JSON следует хранить в защищённом месте — она содержит имена клиентов.
- Рекомендуется периодически копировать SQLite-файл при остановленном сервере (или делать экспорт JSON).
- Импорт JSON **полностью заменяет** сделки, клиентов и справочники. Перед импортом сохраните текущую резервную копию.
- Это личное приложение без пользователей, ролей, аудита и шифрования базы.

## Проверка

Автоматические тесты проверяют Python API, ограничения SQLite и расчёты. Есть дополнительный тест интерфейса с имитацией API (Playwright + Chromium).

```bash
python -m unittest discover -s tests -v
node tests/core.test.js  # если установлен Node.js
```

## Технологии

Python standard library (`http.server`, `sqlite3`) + HTML/CSS/JavaScript без сборщика, десктопный контейнер `pywebview`, Android WebView. Исходники интерфейса общие для всех платформ.
